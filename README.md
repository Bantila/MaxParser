# MaxParser

Мост между мессенджером Max и Telegram. Сообщения из школьного чата Max приходят
в Telegram — вам в личку и в группу класса. Доверенные люди могут написать боту
в Telegram, и текст уйдёт обратно в чат Max.

Расписания (фото, `.docx` и прочее) пересылаются вложениями как есть — без
распознавания и разбора.

## Установка

```bash
python -m venv .venv
.venv\Scripts\pip install maxapi-python httpx python-dotenv
copy .env.example .env
```

Заполните `.env`, затем узнайте ID школьного чата и впишите его в `MAX_CHAT_ID`:

```bash
.venv\Scripts\python bridge.py chats
```

При первом запуске Max пришлёт SMS-код. Дальше сессия хранится в `cache/max.db`
и код больше не нужен.

## Запуск

```bash
.venv\Scripts\python bridge.py
```

Проверка логики без сети:

```bash
.venv\Scripts\python test_bridge.py
```

## Как это устроено

```
Max (школьный чат) ──on_message──► Telegram: TG_TARGETS
                                   текст как текст, вложения как документы

Telegram getUpdates ──TG_TRUSTED──► Max: send_message в MAX_CHAT_ID
```

Всё в одном файле `bridge.py`.

## О чём стоит помнить

**Сообщения уходят от вашего имени.** Мост работает через ваш аккаунт Max,
поэтому в школьном чате всё выглядит как ваши собственные сообщения. Отличить
невозможно. Отсюда два правила:

- в `TG_TRUSTED` попадают только те, за чьи слова вы готовы отвечать лично;
- сообщения не от вас уходят с префиксом `Имя: `, чтобы в чате было видно автора.

**Аккаунт могут заблокировать.** Библиотека `maxapi-python` работает через
внутренний API Max, а не через официальный Bot API (для него нужен верифицированный
профиль организации или ИП). Авторы библиотеки прямо предупреждают, что это может
нарушать условия сервиса и что за блокировки они не отвечают. Аккаунт при этом тот
самый, который требует школа.

Поэтому `READ_ONLY=true` стоит по умолчанию. Поживите так неделю: если ничего не
прилетело — переключайте на `false` и включайте отправку.

**Внутренний API может измениться** без предупреждения, и мост тогда сломается.

## Что сознательно не сделано

- Расписания не распознаются и не парсятся — файлы идут насквозь.
- Нет базы сообщений и истории за время простоя: пересылается только то, что
  пришло при работающем мосте.
- Нет редактирования и удаления — только новые сообщения.
