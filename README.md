# MaxParser

**Мост между мессенджером Max и Telegram.** Сообщения из школьного чата Max
приходят в Telegram — в личку и в группу класса, с раскладкой по темам. Доверенные
люди отвечают боту в Telegram, и текст уходит обратно в чат Max.

## Задача

Школа перевела родительские чаты в Max. Расписания, отмены уроков и объявления
приходят туда — а вся остальная жизнь идёт в Telegram, и школьный чат в ней
теряется. Ставить второе приложение ради трёх сообщений в неделю никто не хочет,
но пропустить перенос урока нельзя.

Официального Bot API у Max для физлица нет: он требует верифицированный профиль
организации или ИП. Значит, мост может работать только через личный аккаунт — и
всё проектирование дальше упирается в это ограничение.

## Как устроено

```
Max (школьный чат) ──on_message──► Telegram: личка + группа класса
                                   текст как текст, вложения как документы,
                                   раскладка по темам форума

Telegram getUpdates ──TG_TRUSTED──► Max: send_message в MAX_CHAT_ID
```

Один процесс. В одном asyncio-цикле живут постоянное соединение с Max и long
polling Telegram. Состояние — только файл сессии на диске; ни базы, ни очередей,
ни слушающих сокетов, только исходящие соединения.

## Инженерные решения

**Два сетевых пути в одном процессе.** Max требует российский IP, а с
российского IP, как правило, недоступен `api.telegram.org`. Telegram ходит через
SOCKS5-туннель, Max и скачивание вложений — напрямую. Один цикл, два транспорта,
и вложение, скачанное с российского адреса, отдаётся в Telegram через прокси.

**Изоляция отказов на границе обработчика.** Библиотека `maxapi-python`
превращает любое исключение из хендлера в `RuntimeError` и рвёт соединение с Max.
Каждый обработчик гасит исключения у себя: битое вложение или неизвестный тип
сообщения стоят одной строки в логе, а не переподключения.

**Деградация вместо потери.** Не удалось скачать файл — в Telegram всё равно
уходит уведомление, что файл был, с именем и типом. Про сообщение узнают в любом
случае; молча пропасть оно не может.

**Работа с чужими протоколами по факту, а не по документации.** Telegram Bot API
отвечает `200 OK` на отказ — статус ничего не значит, ошибку приходится доставать
из тела. Тема «General» имеет номер `1`, но API его не принимает: в неё пишут
вообще без `message_thread_id`. Фото отправляются документом, без сжатия — иначе
мелкий текст на снятом расписании становится нечитаемым, — но в «тему Фото»
попадают, потому что вид вложения берётся из данных Max, а не из способа отправки.

**Безопасный дефолт.** `READ_ONLY=true` из коробки: обратный канал в Max выключен,
пока его не включат сознательно. Цена ошибки здесь — блокировка личного аккаунта,
того самого, который требует школа, поэтому по умолчанию мост только читает.

**Деплой, который не задевает соседей по серверу.** SOCKS-порт `21080` вместо
типичного `1080` и только на `127.0.0.1` — анонимный прокси наружу не открывается.
Отдельный SSH-ключ, префикс проекта в имени systemd-юнита, лимит 256 МБ памяти.
Сервер редко бывает пустым.

**Тесты без сети.** `app/test_bridge.py` проверяет маршрутизацию по темам, разбор
списков ID и форматирование на заглушках — ни аккаунта Max, ни бота для прогона
не нужно.

## Границы решения

Проект намеренно не делает больше, чем должен: расписания не распознаются и не
парсятся, истории за время простоя нет, редактирование и удаление не
поддерживаются. Риски работы через личный аккаунт разобраны честно и вынесены в
отдельный раздел — [О чём стоит помнить](#о-чём-стоит-помнить).

## Установка

Дальше — руководство по развёртыванию: Windows локально и Linux через Docker
Compose, с прокси-туннелем для Telegram.

## Что понадобится заранее

Три вещи, без которых ни один из способов установки не заработает.

**1. Включённая 2FA в аккаунте Max.** Max отклоняет вход сторонних клиентов без
двухфакторной аутентификации — вы получите ошибку `error.profile.active.session.no2fa`.
Включается в приложении: Настройки → Безопасность → Пароль для входа. Опция
появляется, только если вы залогинены на устройстве больше 24 часов. Придуманный
пароль понадобится в `.env`.

**2. Telegram-бот.** Напишите [@BotFather](https://t.me/BotFather), команда
`/newbot`, придумайте имя. В ответ придёт токен вида `123456789:AAE...`.

**3. Ваш Telegram ID.** Напишите [@userinfobot](https://t.me/userinfobot), он
ответит числом. Если планируете группу класса — добавьте туда бота и возьмите ID
группы там же, он будет отрицательным.

## Установка на Windows (локально)

Нужен Python 3.12 или новее. Проверить: `python --version`.

```powershell
git clone https://github.com/Bantila/MaxParser.git
cd MaxParser
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
```

Откройте `.env` в любом редакторе и заполните. **Не запускайте `copy` повторно** —
эта команда молча затирает заполненный файл шаблоном.

```ini
MAX_PHONE=+79001234567
MAX_PASSWORD=ваш_пароль_2fa
TG_TOKEN=123456789:AAE...
TG_TARGETS=987654321
TG_TRUSTED=987654321
READ_ONLY=true
```

Теперь узнайте ID школьного чата:

```powershell
.venv\Scripts\python app\bridge.py chats
```

При первом запуске Max пришлёт SMS-код — введите его в консоли. Дальше сессия
хранится в `cache/max.db`, и код больше не нужен. Команда выведет список чатов
с их ID; найдите школьный и впишите его в `MAX_CHAT_ID` в `.env`.

Запуск моста:

```powershell
.venv\Scripts\python app\bridge.py
```

Запускать **из корня проекта**: путь к `cache/` берётся от текущей директории.

Проверка логики без сети:

```powershell
.venv\Scripts\python app\test_bridge.py
```

## Установка на Linux через Docker

Нужны Docker и плагин Compose. Проверить: `docker compose version`.

```bash
git clone https://github.com/Bantila/MaxParser.git
cd MaxParser
cp .env.example .env
nano .env          # заполните так же, как в разделе выше
docker compose build
```

**Первый запуск обязательно интерактивный** — Max спросит код из SMS, а в фоне
ввести его некуда:

```bash
docker compose run --rm max-backend
```

Введите код, дождитесь строки `Мост запущен`, затем `Ctrl+C`. Убедитесь, что
файл `cache/max.db` появился — значит сессия сохранена и больше SMS не потребуется.

Узнайте ID школьного чата и впишите его в `.env`:

```bash
docker compose run --rm max-backend python bridge.py chats
```

Теперь можно уходить в фон:

```bash
docker compose up -d
docker compose logs -f
```

Мост переживает перезагрузку сервера — за это отвечает `restart: unless-stopped`.

### Прокси для Telegram

С российского адреса `api.telegram.org`, как правило, недоступен — в логах это
`httpx.ConnectTimeout`. Проверить:

```bash
curl -sI --max-time 10 https://api.telegram.org || echo "нужен туннель"
```

Прокси делается SSH-туннелем на любой зарубежный сервер, куда у вас есть доступ.
Ничего устанавливать не нужно: `ssh -D` умеет это сам.

Заведите отдельный ключ, чтобы не трогать существующие:

```bash
ssh-keygen -t ed25519 -f /root/.ssh/maxparser-tunnel -N ""
ssh-copy-id -i /root/.ssh/maxparser-tunnel.pub root@YOUR_SERVER
ssh-keyscan -H YOUR_SERVER >> /root/.ssh/known_hosts
```

Последняя строка обязательна: юнит запускается с `BatchMode=yes` и без неё
упадёт на подтверждении ключа хоста.

Проверьте вручную, затем поставьте юнит:

```bash
ssh -i /root/.ssh/maxparser-tunnel -o BatchMode=yes root@YOUR_SERVER echo ok
```

Команда обязана вывести `ok` и ничего не спросить. Если просит пароль — ключ не
доехал, и юнит упадёт на том же месте.

Правим копию в `/etc`, а не файл в репозитории, иначе следующий `git pull`
упрётся в конфликт:

```bash
cp deploy/maxparser-tunnel.service /etc/systemd/system/
sed -i 's/YOUR_SERVER/адрес.вашего.сервера/' /etc/systemd/system/maxparser-tunnel.service
systemctl daemon-reload
systemctl enable --now maxparser-tunnel
```

Убедитесь, что туннель поднялся и работает:

```bash
systemctl status maxparser-tunnel
ss -ltnp | grep 21080
curl --socks5 127.0.0.1:21080 -sI https://api.telegram.org | head -1
```

Последняя команда должна вернуть `HTTP/1.1 200 OK`. Теперь в `.env`:

```
TG_PROXY=socks5://127.0.0.1:21080
```

**Что сделано, чтобы не задеть соседей по серверу.** Порт 21080 вместо типичного
1080 и только на `127.0.0.1` — снаружи он не виден, анонимный прокси в интернет
не открывается. Ключ отдельный, существующие не затрагиваются. Имя юнита
с префиксом проекта. Контейнер работает в `network_mode: host`, но портов не
слушает, поэтому занять чужой не может, и ограничен 256 МБ памяти.

### Обновление

```bash
git pull
docker compose up -d --build
```

Сессия лежит в `./cache` на хосте и пересборку переживает.

### Полезные команды

```bash
docker compose ps                  # статус контейнера
docker compose logs --tail 50      # последние строки лога
docker compose restart             # перезапустить
docker compose down                # остановить и удалить контейнер
```

`docker compose down -v` использовать **не нужно** — флаг `-v` сносит тома, а
вместе с ними и сессию Max, после чего SMS-код придётся вводить заново.

## Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `MAX_PHONE` | да | Номер аккаунта Max в формате `+7...` |
| `MAX_PASSWORD` | да | Пароль 2FA. Пустой — спросят в консоли, но в фоне спрашивать некого |
| `MAX_CHAT_ID` | нет | ID школьного чата. Пусто — пересылаются **все** чаты |
| `TG_TOKEN` | да | Токен бота от @BotFather |
| `TG_PROXY` | зависит | Прокси для Telegram. Нужен, если сервер не достаёт `api.telegram.org` |
| `TG_TARGETS` | да | Куда пересылать: ваш ID и/или ID группы, через запятую |
| `TG_TRUSTED` | да | Кому можно писать в Max. **Свой ID ставьте первым** |
| `TG_GROUP` | нет | ID группы класса. Не дублируйте её в `TG_TARGETS` |
| `TG_TOPICS` | нет | `1` — раскладывать по темам, `0` — слать в группу одним потоком |
| `TG_TOPIC_TEXT` | нет | Номер темы для текстовых сообщений |
| `TG_TOPIC_PHOTO` | нет | Номер темы для фотографий |
| `TG_TOPIC_FILE` | нет | Номер темы для файлов, видео и голосовых |
| `TG_TOPIC_ALL` | нет | Тема, куда падает всё подряд |
| `READ_ONLY` | нет | `true` (по умолчанию) — только чтение, отправка выключена |

Порядок в `TG_TRUSTED` важен: сообщения первого в списке уходят в Max как есть,
остальных — с префиксом `Имя: `.

## Команда /load

Напишите боту в Telegram, чтобы подтянуть последние сообщения из чата Max:

```
/load        - последние 10
/load 30     - последние 30, максимум 50
```

Сообщения проходят обычным путём, с раскладкой по темам — удобно проверить, что
мост доставляет, не дожидаясь, пока кто-нибудь напишет в школьный чат.

Команда доступна только тем, кто указан в `TG_TRUSTED`, и работает даже при
`READ_ONLY=true`: она читает Max, а не пишет в него. Ваши собственные сообщения
пропускаются — мост не пересылает то, что отправлено с его же аккаунта.

## Раскладка по темам в группе

Если в группе класса включены темы, мост может раскладывать по ним: текст в одну,
фотографии во вторую, файлы в третью, и отдельная тема, куда падает всё подряд.

Включите темы в настройках группы, добавьте туда бота, затем узнайте номера тем:
откройте тему, на любом сообщении в ней «Копировать ссылку». Получится вида
`t.me/c/2582.../3/12` — номер темы это предпоследнее число, здесь `3`.

Для темы «General» ставьте `1`. Номер у неё действительно такой, но Bot API его
не принимает и отвечает `message thread not found` — в General пишут вообще без
указания темы. Мост подставляет единицу правильно, так что просто укажите `1`.

```ini
TG_GROUP=-1001234567890
TG_TOPICS=1
TG_TOPIC_TEXT=2
TG_TOPIC_PHOTO=3
TG_TOPIC_FILE=4
TG_TOPIC_ALL=5
```

Любую тему можно оставить пустой — тогда этот вид просто не будет туда уходить.
`TG_TOPICS=0` отключает раскладку целиком: группа останется в получателях, но всё
пойдёт в неё одним потоком, номера тем при этом игнорируются.

Фотографии отправляются файлом, без сжатия — иначе мелкий текст на снятом
расписании становится нечитаемым. В тему «Фото» они всё равно попадают: вид
вложения определяется по данным из Max, а не по способу отправки.

**Группу, указанную в `TG_GROUP`, нужно убрать из `TG_TARGETS`** — иначе каждое
сообщение придёт дважды. В `TG_TARGETS` оставьте только личку.

## О чём стоит помнить

**Сообщения уходят от вашего имени.** Мост работает через ваш аккаунт Max,
поэтому в школьном чате всё выглядит как ваши собственные сообщения. Отличить
невозможно. Отсюда два правила:

- в `TG_TRUSTED` попадают только те, за чьи слова вы готовы отвечать лично;
- сообщения не от вас уходят с префиксом `Имя: `, чтобы в чате было видно автора.

**Аккаунт могут заблокировать.** Библиотека `maxapi-python` работает через
внутренний API Max, а не через официальный Bot API (для него нужен верифицированный
профиль организации или ИП). Авторы библиотеки прямо предупреждают, что это может
нарушать условия сервиса и что за блокировки они не отвечают. Аккаунт при этом тот
самый, который требует школа.

Поэтому `READ_ONLY=true` стоит по умолчанию. Поживите так неделю: если ничего не
прилетело — переключайте на `false` и включайте отправку.

**Хостинг повышает риск.** Max ожидает, что личный аккаунт живёт с мобильного или
домашнего адреса. Вход с датацентрового IP выглядит подозрительно сам по себе;
если сервер вдобавок ходит наружу через VPN и отдаёт нероссийский адрес, вход,
скорее всего, не пройдёт вовсе. Проверить исходящий адрес: `curl ipinfo.io/country`.

**Российский сервер и Telegram — конфликт.** Max требует российский IP, а с него,
как правило, недоступен `api.telegram.org`. В логах это выглядит как
`httpx.ConnectTimeout` при отправке сообщения. Лечится переменной `TG_PROXY`:
Telegram пойдёт через прокси, а Max останется на прямом соединении. Проверить,
есть ли проблема:

```bash
curl -sI --max-time 10 https://api.telegram.org || echo "Telegram недоступен, нужен TG_PROXY"
```

**Внутренний API может измениться** без предупреждения, и мост тогда сломается.

**Чужие сообщения.** В Telegram уезжает то, что писали учитель и одноклассники.
В рамках своего класса это терпимо, но людей стоит предупредить.

## Что сознательно не сделано

- Расписания не распознаются и не парсятся — файлы идут насквозь.
- Нет базы сообщений и истории за время простоя: пересылается только то, что
  пришло при работающем мосте.
- Нет редактирования и удаления — только новые сообщения.
